# 번호 선정 방식

## 2026-11-23부터 적용하는 선택 기준

매주 같은 당첨 이력으로 후보 묶음을 만듭니다. `screened`는 최근 성과로 기법을 선별하는 v7이고, `cluster`는 이월수·이웃수·동반 출현 등을 이용해 번호를 모으는 방식입니다. v7의 번호별 추정 확률이 균등하고 10장을 생성할 때는 겹치는 번호를 다르게 배치한 후보도 비교합니다.

추가 후보는 첫 6장 중 어떤 두 장을 골라도 번호 하나를 공유하게 만듭니다. 이렇게 번호 15개를 두 번씩 쓰고, 첫 6장에 고유 번호 하나씩을 더합니다. 나머지 24개 번호는 뒤의 4장에 한 번씩 씁니다. 번호 배정은 회차별 시드로 섞습니다. 공정 추첨에서 이 배치가 한 장 이상 5등에 해당하거나 그 이상이 되는 경우는 전체 8,145,060개 중 1,875,065개(23.0209%)입니다.

각 후보의 10장 중 어느 한 장에서 본번호 3개 이상을 맞히는 경우를 모두 세어 가장 많은 묶음을 고릅니다. 동률이면 4개 이상인 경우를 비교하고, 여기서도 동률이면 기존 후보를 우선합니다. 기존에 저장된 예측은 원래 번호로 검토합니다. 공정 추첨에서 서로 다른 10장의 1등 확률은 모든 배치에서 10/8,145,060입니다. 무작위로 서로 다른 10장을 고를 때 5등 이상에 한 장이라도 당첨될 확률은 평균 21.43%입니다. 각 생성기의 종합점수는 단위가 달라 묶음 비교에는 쓰지 않습니다.

## v7 후보 내부의 번호 선정

2026-10-12에 v7(`screened_whole_ticket_v7`)에 6개 전체 조합 선택 단계를 추가했습니다.

기법별 검증에서 근거가 부족한 특징을 제외하고, 별도 후속 구간에서 결합 모델 반영 강도를 결정합니다. 각 과거 시점의 이력만 사용합니다. 자세한 순서는 `주간분석개선.md`에 있습니다.

당첨 본번호 6개가 여러 세트 전체에 들어 있는 것과, 한 세트에서 6개를 모두 맞히는 것은 다릅니다. 저장된 1244·1245회 예측은 각각 전체에 본번호 6개가 있었지만 한 세트의 최고 적중은 2개였습니다. 저장 시점 증거가 부족한 기록의 재채점이며 사전 예측 성과 인증은 아닙니다.

기법별 선별과 반영 강도 검증은 기존대로 추첨 이전 자료만 사용합니다. 그 뒤 `select_whole_ticket_portfolio`가 완전한 6개 조합을 선택합니다. 1~10세트를 지원하며 5세트와 10세트 모두 검증했습니다.

- 검증 후 번호별 추정치 q에 차이가 있으면, 포함 오즈 `q / (1-q)` 여섯 개의 곱이 가장 큰 서로 다른 조합을 선택합니다. 번호 사용 횟수를 먼저 균등화하여 높은 후보들을 강제로 분해하는 제약은 적용하지 않습니다.
- 번호별 독립 포함을 ‘정확히 6개’로 조건화한 모델에서 위 곱은 조합 질량에 비례합니다. 서로 다른 조합의 전체 일치 사건은 배타적이므로, 상위 5개 또는 10개 선택은 **이 모델 안에서** 전체 일치 질량 합을 최대화합니다. 과거 정답을 보고 재조합하거나 모의 표본의 우연한 적중을 최적화하지 않습니다.
- q가 모두 같으면 모든 조합의 모델 질량도 같습니다. 기존 분산 선택을 유지해 임의 동점 순위 때문에 공통 5개를 모든 세트에 고정하는 문제를 피합니다. `selection_policy=balanced_uniform_tie`로 구분됩니다. 이 정책의 10세트만 1~45 전체 포함·번호당 최대 2회 조건을 갖습니다.

비균등 선택은 `selection_policy=top_distinct_whole_tickets`입니다. 공통 번호가 반복되거나 전체 번호 커버리지가 줄 수 있습니다. 전체 6개 일치와 부분 적중을 넓게 확보하는 선택의 목적은 다릅니다. 평균/최고 부분 적중이나 실제 1등 확률의 향상을 보장하지 않습니다. 독립 포함 가정도 실제 추첨에서 검증된 결합 확률이 아닙니다. q 강도를 변경해도 조합 순위가 같으면 선택 번호가 같을 수 있으며 모델 질량은 별도로 계산됩니다.

균등 추첨에서 서로 다른 5세트·10세트의 6개 전체 일치 확률은 각각 `5 / C(45,6)`, `10 / C(45,6)`입니다. 세트 사이 겹침이나 전체 커버리지와 관계없이 같은 세트 수에는 같습니다. 당첨번호를 알고 재조합하는 예를 미래 예측력으로 해석하지 않습니다.

저장 예측 비교와 화면 요약은 본번호만 평가하고 보너스는 따로 셉니다.

| 지표 | 의미 |
|---|---|
| `union_main_hits` | 전체 세트를 합쳐 포함한 당첨 본번호 수 |
| `best_main_hits` | 한 세트의 최고 본번호 적중 수 |
| `fragmentation_gap` | 전체 포함 수 − 한 세트 최고 적중 수 |
| `all_six_scattered` | 전체에는 6개가 있으나 6개 적중 세트가 없음 |
| `exact_six_sets` | 본번호 6개를 맞힌 세트 수 |
| `sets_at_least` | 3·4·5·6개 이상 적중 세트 수 |

생성 근거의 `combination_selection`에는 선택 목적, 정책, 조합별 모델 질량과 포트폴리오 모델 질량 합을 제공합니다. 전체 조합을 열거하지 않고 로그 공간의 대칭합으로 정규화하며 실제 당첨확률로 해석하지 않습니다.

v7의 종합점수는 세트 내 여섯 번호의 포함 추정치 합입니다. 균등 추정치이면 모든 세트 점수는 0.8입니다. `cluster`의 종합점수는 자체 규칙으로 매긴 점수입니다.

기법이 적용 기준을 통과하지 못하면 균등확률과 번호 노출 분산을 사용합니다. 보너스 보조 신호는 본번호 특징에서 정책상 제외합니다. 실제 적용 기법은 각 실행의 `effective_methods`로 확인하며 이전 실행의 판단을 고정하지 않습니다.

2026-10-12에 1186~1245회 60개 과거 대상 회차를 추첨 이전 이력만 사용해 재생했습니다. 세트 수별 일반 무작위 기준은 100회 반복했습니다. 이 구간에서는 실제 신호 적용이 0회였고 v7·v6 분산 선택·균등 대조군의 조합이 모두 같았습니다.

| 예산 | 세트당 적중 평균 | 한 세트 최고 적중 평균 | 최고 3개 이상 회차 | 최고 4·5·6개 이상 회차 | 6개가 흩어진 회차 |
|---|---:|---:|---:|---:|---:|
| 5세트 | 0.8067 | 1.7333 | 4 / 60 | 모두 0 / 60 | 4 / 60 |
| 10세트 | 0.8033 | 2.1333 | 12 / 60 | 모두 0 / 60 | 60 / 60 |

따라서 실제 적중 개선은 확인되지 않았습니다. 상위 후보 6개를 한 세트로 유지하는 동작과 모델 목적함수는 합성 입력으로 검증했고 실제 예측력과 구분합니다. 균등 추정치에서 번호만 다시 묶어 1등 확률을 높일 근거는 없습니다.

비교 명령은 `python -B lotto/benchmark_audit.py --sets 5` 또는 `--sets 10`입니다. 새 선택기는 다음 미관측 회차의 생성 경로에 반영되며 이미 저장된 예측번호를 자동 교체하지 않습니다. v6의 과거 결과는 `.agent/AGENT.md` 10절, v7 검증은 11절에 있습니다.
