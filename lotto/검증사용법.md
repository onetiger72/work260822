# 최종 번호 검증

`python lotto/review_predictions.py`는 기존 CSV를 변경하지 않고 저장된 다음 회차 후보를 검토합니다. 기본은 `manual` 모드입니다.

본 실행 파일 `로또 당첨번호 예측.py`에도 저장 직전 동일 검증을 연결했습니다. 기존 예측이 있더라도 검증합니다. 구형 `lotto.py`, `lotto_engine.py`에는 연결하지 않았습니다.

- 당첨 이력 전체의 정수·범위·중복·누락·회차별 날짜를 검사합니다.
- 최신 회차를 공식 API에서 다시 조회해 본번호와 보너스를 대조합니다.
- 직전 회차 예측을 재채점하고 다음 회차 후보 전부를 GPT에 전달합니다.
- GPT 응답의 입력 SHA256, 대상 회차, 검토 세트 목록을 재검사합니다.
- 공식 조회 실패, 키 누락, 응답 오류는 최종 통과가 아닙니다. 형식 오류·공식 불일치·GPT reject는 본 실행 파일의 예상번호 저장을 중단합니다. 검토 대기 후보는 기존 CSV 형식으로 저장하되 대기 상태를 출력합니다.

자동 GPT 호출은 PowerShell 환경변수 `LOTTO_FINAL_REVIEW_MODE=api`, `OPENAI_API_KEY`, 필요시 `LOTTO_LLM_MODEL`을 설정합니다. 키를 코드나 파일에 기록하지 마세요. 기존 `LOTTO_LLM_MODE` 가중치 감사 설정과는 별개입니다.

수동 검토는 `GPT최종검증요청.json`을 GPT로 검토하고 제공된 응답 스키마에 맞춰 `GPT최종검증제안.json`에 저장한 뒤 재실행합니다. 입력이 바뀌면 이전 제안은 거부되므로 다시 검토해야 합니다. 수동 파일은 로컬의 신뢰된 검토 기록이며 모델 신원을 인증하는 서명이 아닙니다.

`GPT최종검증결과.json`의 `finalized: true`는 해당 입력의 품질·일관성 검토 통과만 의미합니다. 실제 당첨번호 예측의 정확성이나 수익성을 뜻하지 않습니다. 저장된 과거 예측에는 생성 시점 증빙이 없어 실전 예측력 인증에는 사용할 수 없습니다.

API 구현 참고: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

테스트: `python -m unittest discover -s lotto -p test_lotto_validation.py -v`
