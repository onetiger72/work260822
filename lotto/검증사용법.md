# 주간 번호 생성과 검토

이 대화에서 **“이번 회차 번호를 검증하고 실행해줘”**라고 요청하면 된다. 두 명령 모두 같은 실행 절차를 사용한다.

```powershell
python -B "lotto/로또 당첨번호 예측.py" --review-session
python -B lotto/lotto.py --review-session
```

1. 프로그램이 당첨 이력과 예측 CSV를 검증하고, 동행복권에서 마지막 저장 회차와 누락 결과를 확인한다. 유효한 추첨 결과를 당첨 이력에 반영하고 기존 예측을 메모리에서 재채점한다.
2. 기존 집중 방식과 v7 방식이 각 10세트를 만든다. 각 묶음에 대해 가능한 당첨번호 8,145,060개를 평가한다. 한 장 이상 본번호 3개 이상을 맞히는 경우가 많은 묶음을 선택하고, 동률이면 4개 이상 경우의 수, 그다음 v7 순으로 선택한다. 이미 해당 회차에 저장한 번호는 그대로 검토한다.
3. 프로그램이 후보, 공식 결과, 적용 기법, 생성 코드 해시, 비교표와 입력 SHA256을 출력한다. 이 대화에서 각 세트와 계산을 검토한 뒤 검토자가 입력 해시, 회차, 세트 ID 전체, 판단 근거와 판정을 한 줄 JSON으로 돌려준다. 이 모드는 외부 모델 API 키가 필요 없다.
4. 공식 결과 일치와 동일한 입력에 대한 `pass`를 확인하고, 한국 시간 토요일 20시 판매 마감 전에 예상번호 CSV를 저장한다. 이전 회차의 세트는 보존하고 최신 결과에 해당하는 평가 열을 갱신한다. 저장 도중 다른 실행이 파일을 고치면 새 검토가 필요하다. 대화에 남긴 확정 시각과 검토 해시는 다음 주 재채점에 사용한다.

공정한 추첨에서 서로 다른 10세트의 1등 확률은 10/8,145,060이다. 비교표의 3개 이상 확률은 **10장 중 하나 이상이 5등 이상**일 확률이다. 종합점수는 생성기마다 정의가 다르다.

기본 수동 모드로 F5나 옵션 없는 명령을 실행하면 검토 요청을 출력한다. 당첨 이력은 갱신될 수 있고, 예측 파일 저장에는 검토 응답이 필요하다. 여러 실행에 걸쳐 검토할 때는 `--manual-response`로 응답 JSON을 표준입력에 전달한다. `LOTTO_FINAL_REVIEW_MODE=api` 설정은 별도 API 검토를 사용하며 `--review-session`은 항상 이 대화에서 수동 검토한다.

```powershell
# 두 CSV와 모델을 읽기 전용으로 점검
python -B lotto/lotto.py --audit-only
# 공식 결과를 조회하지 않는 로컬 점검
python -B lotto/lotto.py --audit-only --offline
# 자동 테스트
python -B -m unittest discover -s lotto -p "test_lotto*.py" -q -b
```
