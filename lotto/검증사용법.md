# 최종 번호 검증

`python lotto/review_predictions.py`는 기존 CSV를 변경하지 않고 저장된 다음 회차 후보를 검토합니다. 기본은 `manual` 모드이며 검토 요청·결과 파일을 생성하지 않습니다.

본 실행 파일 `로또 당첨번호 예측.py`에도 저장 직전 동일 검증이 연결되어 있습니다. 기존 예측이 있더라도 검증합니다. 구형 `lotto.py`, `lotto_engine.py`에는 연결하지 않았습니다.

- 당첨 이력 전체의 정수·범위·중복·누락·회차별 날짜를 검사합니다.
- 최신 저장 회차를 공식 API에서 다시 조회해 본번호와 보너스를 대조합니다. 일반 생성은 별도로 최신 완료 회차 누락도 차단합니다.
- 직전 회차 예측을 재채점하고 다음 회차 후보 전체를 검토 입력에 포함합니다.
- 응답의 입력 SHA256, 대상 회차, 검토 세트 목록을 재검사합니다.
- 공식 조회 실패, 키 누락, 응답 오류는 최종 통과가 아닙니다. 형식 오류·공식 불일치·reject는 일반 실행의 예상번호 저장을 중단합니다. 검토 대기 후보는 기존 CSV 형식으로 저장될 수 있으므로 화면의 상태를 구분해야 합니다.

자동 GPT 호출은 환경변수 `LOTTO_FINAL_REVIEW_MODE=api`, `OPENAI_API_KEY`, 필요시 `LOTTO_LLM_MODEL`을 설정합니다. 키를 코드나 파일에 기록하지 마세요.

수동 검토는 화면에 출력된 요청 객체를 검토하고, 그 안의 응답 스키마에 맞춘 응답 객체를 표준입력으로 전달합니다. 중간 파일은 필요하지 않습니다.

```powershell
# 응답 객체를 문자열 변수에 준비한 뒤 전달
$reviewResponse | python lotto/review_predictions.py --manual-response
```

주 실행 파일도 `--manual-response`를 지원합니다. Python에서는 `final_review(..., manual_review=응답객체)`로 전달할 수 있습니다. 입력이 바뀌면 이전 응답은 통과하지 못하므로 다시 검토합니다. 수동 응답은 모델 신원을 인증하는 서명이 아닙니다.

`final_review(...)`는 상태, 확정 여부, 요청 및 결과를 사전으로 반환합니다. 일반 저장 함수는 반환 DataFrame의 `attrs["final_review"]`로 이를 제공합니다. `finalized: true`는 해당 입력의 품질·일관성 검토 통과이며 당첨 정확성이나 수익성을 뜻하지 않습니다.

검토 상태를 별도 파일에 보관하지 않으므로 다음 실행에서 다시 확인해야 합니다. 예상번호 CSV에 존재한다는 것만으로 이전 확정 여부를 판단하지 않습니다. 과거 예측의 추첨 전 생성 시점도 인증하지 않습니다.

테스트: `python -B -m unittest discover -s lotto -p "test_lotto*.py" -q -b`
