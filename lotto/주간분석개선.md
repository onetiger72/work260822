# 주간 분석 점검과 실행

예측 전 점검만 실행:

```powershell
python "lotto/로또 당첨번호 예측.py" --audit-only
```

공식 조회 없는 로컬 점검은 `--offline`을 추가합니다. 이 경우 공식 확인 완료로 표시하지 않습니다. 점검은 `실행전점검.json`만 저장하며 당첨 이력 CSV, 기존 예측 CSV, 금주 예측번호를 생성·변경하지 않습니다. 조회한 새 결과는 보고서에 포함됩니다.

현재 생성기 버전은 `screened_balanced_v5`입니다.

1. 일반 실행은 최신 완료 회차까지 수집하고 전체 이력과 공식 마지막 결과를 확인합니다. 공식 조회 실패·결과 불일치·누락 회차가 있으면 새 예측 생성을 중단합니다.
2. 저장된 예측은 실제 본번호와 다시 비교합니다. 보너스는 별도로 계산합니다.
3. 최근 24회보다 앞선 24회에서 기법별 단독 보정 모델을 평가합니다. 각 회차 학습에는 해당 추첨 이전 자료만 사용합니다. 균등확률 대비 평균 Brier 오차 개선이 회차별 차이의 표준오차 2배를 넘고 최소 12회가 확보된 기법만 유지합니다. 이는 보수적인 선택 규칙이며 통계적 유의성 입증이 아닙니다.
4. 유지된 기법만 입력에 넣어 최근 24회에서 결합 모델의 반영 강도 0%, 25%, 50%, 100%를 검토합니다. 최저 오차와 표준오차 이내인 후보 중 가장 약한 강도를 선택합니다. 검증 자료나 우위 근거가 부족하면 균등확률로 돌아갑니다.
5. 제외 기법은 최종 학습 입력에서 실제로 빠집니다. 다음 실행에서는 재평가합니다. 새 기법은 `ANALYSIS_METHODS`에 등록하면 같은 기준을 통과해야 반영됩니다. 기존 실전 피드백 CSV와 LLM 가중치 제안은 참고용이며 현재 모델 가중치를 직접 바꾸지 않습니다.
6. 최종 10세트는 번호별 사용 횟수를 먼저 균등화하고, 반복 번호쌍을 줄인 뒤 모델 점수를 반영합니다. 45개 번호 전체를 포함하고 번호별 사용은 최대 2회입니다. 각 세트 적중이나 당첨을 보장하지 않습니다.
7. 일반 실행은 `주간분석검토_회차.json`에 제외/유지 근거, 실제 반영 기법, 강도, 번호 집중도를 기록합니다. 기존 회차 예측은 보존하며, 최종 GPT 검증 절차도 유지합니다.

일반 실행: `python "lotto/로또 당첨번호 예측.py"`

회귀 테스트: `python -B -m unittest discover -s lotto -p "test_lotto*.py" -q`

과거 비교: `python -B lotto/benchmark_audit.py` → `실행전비교.json`. 실행 중 신규 특징 캐시를 만들고, 각 대상 회차 이전 자료만 사용합니다. `analysis_cache/portfolio_v4.py`는 변경 전 비교용 사본입니다. 결과를 보고 파라미터를 재탐색하지 않았으며 미래 예측력 입증으로 해석하지 않습니다.
