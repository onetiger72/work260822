# 로또 예측 시스템: 다른 LLM을 위한 검토 규칙

작성 기준: 2026-09-28, 생성기 버전 `screened_weighted_balanced_v6`.
프로젝트 루트는 `C:\work`, 코드·데이터 폴더는 `lotto/`이다. 아래 경로와 명령은 프로젝트 루트 기준이다.

이 문서는 현재 구현과 검토 원칙을 전달하는 참고 문서다. 다른 LLM에게 검토를 맡길 때 이 파일을 함께 제공한다. 파일명만으로 자동으로 읽힌다고 가정하지 않는다. 사용자의 최신 요청이 우선이며, 코드가 변경되면 이 문서의 버전·수치·설명도 갱신한다.

## 저장 정책 — 2026-09-28 정리 반영

- 자동으로 영구 저장하는 데이터 파일은 `lotto/과거로또 당첨번호.csv`와 `lotto/당첨예상번호.csv` 두 개뿐이다.
- 성과·피드백·기법별 예측 기록·특징 캐시·주간 점검·최종 검토·백테스트 결과를 별도 CSV/JSON으로 저장하지 않는다. 필요한 계산과 결과는 메모리에서 유지하고 화면에 출력하거나 반환한다.
- 삭제된 중간 파일을 다시 생성하는 우회 경로를 추가하지 않는다. JSON을 API 통신·표준입력·화면 출력에 사용하는 것은 파일 저장과 다르다.
- 점검과 비교용 명령은 두 CSV도 변경하지 않는다. 일반 실행만 당첨 이력 갱신과 기존 예측 재평가·다음 회차 추가를 수행한다.
- 이전 중간 파일 16개와 일회성 CSV 교체 스크립트는 사용자 요청에 따라 삭제했다. 비교용 과거 알고리즘은 수치 계산을 보존하고 불필요한 저장 경로만 제거했다.

## 1. 목적과 해석 원칙

- 과거 추첨 결과 수집 → 저장 예측 재평가 → 기법 검증 및 제외 → 반영 강도 검증 → 세트 생성 → 최종 일관성 검토의 연결을 유지한다.
- 성과표를 저장하는 것과 실제 생성기에 반영하는 것은 다르다. 선택한 특징이 최종 학습 입력으로 전달되는지 호출 경로까지 확인한다.
- 로또 추첨의 예측 우위를 가정하지 않는다. 무작위 기준보다 좋다는 근거가 없으면 균등확률로 돌아간다.
- 번호를 여러 세트에 분산해 동시 실패를 줄이는 효과와, 당첨번호를 더 잘 예측하는 능력을 구분한다.
- 개별 세트 적중, 당첨, 수익, 미래 성능을 보장하지 않는다. LLM의 검토 통과도 당첨 정확성을 뜻하지 않는다.
- 사용자가 실행 전 점검만 요청하면 새 회차 번호를 생성·저장하지 않는다. 결과를 본 뒤 과거 예측을 바꾸어 성과가 좋아진 것처럼 만들지 않는다.


`lotto.py`, `lotto_engine.py`, 기존 모의 선택기는 구형 또는 비교용 경로다. 이름이 비슷하다는 이유로 현재 실행 경로로 오인하지 않는다. 주 실행 파일의 미사용 구형 생성·저장 함수는 정리했다. `select_ranked_portfolio`와 `analysis_cache/portfolio_v4.py`, `analysis_cache/legacy_app.py`의 수치 계산은 비교 기준이므로 새 모델에 맞춰 바꾸지 않는다. 파일 캐시 로딩과 불필요한 저장 함수는 제거했다.

## 3. 공식 결과와 저장 데이터 규칙

- 공식 결과 조회는 동행복권 API `https://www.dhlottery.co.kr/lt645/selectPstLt645Info.do`를 사용하며, 요청 회차와 응답 회차를 대조한다.
- 최신 완료 회차는 한국 시간 토요일 21시를 결과 공개 확인 기준으로 계산한다. 계산된 시각만으로 결과 공개를 확정하지 않으며 공식 조회 성공이 필요하다.
- 본번호는 1~45의 서로 다른 정수 6개다. 보너스도 1~45의 정수이며 본번호와 중복되면 안 된다. 소수·불리언·비정상 값은 허용하지 않는다.
- 이력은 1회부터 마지막 회차까지 누락·중복 없이 이어져야 한다. 추첨 날짜도 회차와 일치해야 한다.
- 다음 예측 대상은 마지막 검증된 회차 + 1이다. 이미 결과를 학습한 회차나 중간 회차를 건너뛴 대상을 예측으로 취급하지 않는다.
- 일반 실행에서 최신 결과 누락, 공식 조회 실패, 공식/저장 결과 불일치는 새 예측 생성 차단 사유다. 오프라인 점검을 공식 확인 완료로 표시하지 않는다.
- 본번호 일치수는 예측 집합과 실제 본번호 집합의 교집합 크기다. 보너스 일치는 별도로 계산하며 본번호 적중수에 합산하지 않는다. `총일치수`를 본번호 적중으로 해석하지 않는다.
- 저장된 평가 숫자를 그대로 신뢰하지 말고 원래 예측번호와 공식 결과로 재계산한다.
- 기존 회차의 예측번호와 CSV 열 구조를 보존한다. 일반 실행은 평가 열을 갱신하고 없는 다음 회차를 추가할 수 있지만, 기존 예측번호를 자동 교체하지 않는다.
- CSV의 파일 부재와 읽기 실패를 구분한다. 신규 실행용으로 부재를 허용한 경우만 빈 이력으로 시작한다. 기존 빈 파일, 잘못된 UTF-8/CSV, 중복 헤더, 열 수 불일치, 접근 오류는 중단 사유다. 예외를 빈 표로 바꾸어 덮어쓰지 않는다.
- 예측회차·세트·번호1~6은 필수다. 누락 회차를 마지막 당첨 회차 + 1로 추정하거나 세트 번호를 새로 만들지 않는다. 정수 검증 전에 `astype(int)`로 소수를 절삭하지 않는다. 중복 행·동일 회차의 동일 세트/동일 조합은 삭제하지 않고 오류로 처리한다.
- 공통 예측 검증은 고정 18열 스키마를 반환한다. 평가 열은 미평가이면 비어 있어도 되지만, 값이 있으면 정수·범위를 검사한다. 실제번호는 여섯 개 전체 또는 모두 빈 값이어야 한다. 점수는 유한한 수만 허용하며 과거 점수를 임의로 재보정하지 않는다.
- 수집은 기존 이력 검증 → 모든 대상 회차의 응답 검증 → 결합 이력 검증 → 한 번 저장 순서다. 도중 실패나 요청/응답 회차·날짜 불일치에서는 저장하지 않는다. 부분 성공 결과로 원본을 대체하지 않는다. 이는 입력/조회 실패에 대한 보존 규칙이며 디스크 쓰기의 원자성을 보장하는 설명은 아니다.
- 일반 실행은 예측 CSV도 수집 전에 검사한다. 주 실행, 점검, 후보 검토, 후보 재생성은 공통 로더를 사용한다. 레거시 파일을 현재 입력 검증 경로로 오인하지 않는다.
- 과거 예측에는 추첨 전 생성 시점을 입증할 자료가 부족하다. 저장 기록 비교와 사후 재생성 백테스트를 실전 예측력 인증으로 표현하지 않는다.

## 4. 시간 순서와 기법 선별 규칙

### 학습과 특징

- 대상 회차의 특징을 계산할 때는 반드시 그 추첨 직전까지의 이력만 사용한다. 평가 대상 또는 이후 회차의 결과가 학습·특징·가중치 선택에 들어가면 데이터 누수다.
- 본번호 포함의 균등 기준은 번호당 `6/45`이다. 현재 보정기는 최근 최대 120개의 과거 학습 사례와 ridge 계수 `120.0`을 사용한다.
- 선형 편차는 0.5배로 줄이며, 포함 추정치는 `[0.04, 0.30]` 범위 및 합계 6 조건으로 보정한다. 이 수치는 모델 설정이지 실제 번호별 당첨 확률을 입증한 값이 아니다.
- `보너스보조신호`는 본번호 보정 특징에서 제외한다. 다른 기법이 과거 보너스를 참고할 수 있다는 것과, 평가 정답에 보너스를 넣는 것은 별개다.

### 기법 선택 구간

- 최근 24회보다 앞선 24회에서 각 기법의 단독 보정 모델을 순차 평가한다.
- 유지 조건은 평가 회차 최소 12개이며, 균등확률 대비 평균 Brier 오차 개선이 회차별 개선 차이의 표준오차 2배를 넘어야 한다.
- 기준 미달 기법은 최종 보정 학습 입력에서 실제로 제외한다. 다음 실행에서 다시 평가하므로 영구적인 코드 삭제와는 다르다.
- 이 규칙은 보수적인 선택 기준이다. 다중 비교까지 보정한 통계적 유의성 검정이나 미래 성능 입증으로 설명하지 않는다.

### 후속 반영 강도 구간

- 선택한 기법을 고정하고, 그 뒤 최근 24회에서 결합 모델과 균등확률의 혼합 강도 `0%, 25%, 50%, 100%`를 비교한다.
- Brier 오차가 가장 낮은 후보와의 회차별 차이를 사용한다. 최저 오차와 표준오차 이내인 후보 중 가장 약한 강도를 선택한다.
- 검증 자료가 부족하거나, 선택한 기법이 없거나, 강도가 0%이면 균등확률을 적용한다.
- 최종 적용 기법은 메모리 검토 결과와 화면 출력의 `effective_methods`로 확인한다. `selected_methods`가 있어도 강도가 0%이면 실제 적용 기법은 없다.
- 기법 선별과 강도 검증에 사용한 성적은 튜닝 자료다. 별도의 바깥 구간 검증 또는 미래 실전 검증 없이 독립 성능으로 주장하지 않는다.

### 새 기법 추가

- `ANALYSIS_METHODS`에 등록하고 번호 1~45에 대한 유한한 점수를 반환하도록 구현한다. 특징 계산은 전달받은 과거 이력만 사용해야 한다.
- 새 기법도 동일한 선별·강도 검증 경로를 거쳐야 한다. 최근 실패 한 회차의 당첨번호를 우대하거나 검증 없이 높은 가중치를 부여하지 않는다.
- 기존 실전 피드백 CSV·기법별 예측 CSV·LLM 가중치 제안 파일 경로는 제거했다. 현재 생성기는 과거 당첨 이력에서 기법을 검증한다. 기존 예측 성과는 예상번호 CSV로 메모리에서 계산한다.
- 결과를 본 뒤 기준을 반복 조정하면 그 평가 구간은 더 이상 독립 검증이 아니다. 변경 근거와 새로운 검증 구간을 명시한다.

## 5. 10세트 선택 규칙

- 기본은 서로 다른 본번호 6개로 이루어진 10세트다. 현재 선택기 인수는 1~10세트를 지원하나, 전체 45개 포함 설명은 10세트 기준이다.
- 선택 우선순위는 번호별 기존 사용 횟수 최소화 → 같은 번호쌍 재사용 최소화 → 모델 추정치 크기에 따른 가중 추출이다.
- 마지막 우선순위는 번호별 `-log(U) / (q / (1-q))` 값이 작은 순서다. 각 선택 슬롯에서 45개 난수를 사용하며 시드가 같으면 같은 난수열을 쓴다. q의 순위만 보는 v5와 달리 균등확률과 혼합하는 강도 25/50/100%가 실제 선택에 영향을 줄 수 있다. 강도마다 반드시 다른 조합이 나온다는 뜻은 아니다.
- 노출/번호쌍 제약이 확률 가중치보다 우선한다. 따라서 입력 q와 최종 선택 빈도는 같지 않다. 이 가중 추출을 실제 추첨 확률이나 조건부 베르누이의 정확한 표본 추출로 설명하지 않는다.
- 10세트는 1~45 전체를 포함하며 번호당 최대 2회 사용한다. 동일 입력과 동일 시드는 동일 결과를 내야 한다.
- 45개를 모두 포함하므로 10세트 전체가 본번호 0개가 되는 경우를 구조적으로 막는다. 이것은 개별 세트 적중이나 당첨을 보장하지 않으며 예측력 개선 증거도 아니다.
- 한 세트 안 중복, 범위 오류, 동일 세트 중복, 일부 번호의 과도한 집중을 확인한다. 번호쌍 중복 감소는 선택 우선순위이며 별도의 최적화 보장으로 과장하지 않는다.
- `조합점수` 및 저장 CSV의 `종합점수`는 해당 번호들의 포함 추정치 합이다. 1등 당첨확률이 아니다. 균등확률이면 세트당 점수는 0.8이다.
- 과거 상위 점수 조합만 고르던 방식으로 되돌리려면 번호 집중과 회차별 최고 적중 저하를 포함해 검증해야 한다.

## 6. 점검 모드와 최종 검토 상태

```powershell
# 새 번호 없이 공식 결과 조회 및 로직 점검
python "lotto/로또 당첨번호 예측.py" --audit-only

# 네트워크 없이 로컬 점검: 공식 확인 완료가 아님
python "lotto/로또 당첨번호 예측.py" --audit-only --offline

# 실제 수집·평가·다음 회차 생성 작업을 요청받았을 때 사용
python "lotto/로또 당첨번호 예측.py"

# 저장된 다음 회차 후보 검토: 새 번호 생성용 명령이 아님
python lotto/review_predictions.py
```

- `--audit-only`는 공식 새 결과와 기존 예측 재채점, 기법별 판단을 메모리에서 계산해 화면에 출력하고 반환한다. 파일을 만들거나 당첨 이력·예측 CSV를 변경하지 않는다.
- 일반 실행의 최종 검토는 전체 후보, 직전 예측 비교, 공식 대조 상태, 입력 SHA256, 대상 회차 및 검토한 세트 ID를 확인한다.
- `LOTTO_FINAL_REVIEW_MODE`는 기본 `manual`, API 모드는 `api`다. 미사용 가중치 감사용 `LOTTO_LLM_MODE` 처리 경로는 제거했다.
- API 키는 환경변수로만 제공하며 코드·CSV·보고서·대화에 기록하지 않는다.
- 수동 검토 요청은 화면에 출력한다. 응답 객체는 `--manual-response` 옵션의 표준입력 또는 `final_review(..., manual_review=응답객체)`로 전달한다. 입력 해시가 달라진 응답은 재사용하지 않는다. 수동 응답은 모델 신원을 인증하는 서명이 아니다.
- 공식 일치와 유효한 `pass`가 함께 있어야 `finalized: true`가 된다. 이는 데이터·후보의 일관성 검토 통과를 뜻한다.
- 현재 저장 흐름은 `validation_error`, `source_mismatch`, `reject`에서 중단한다. 검토 대기 후보는 CSV에 저장될 수 있으므로, **파일에 존재한다는 것과 최종 확정을 구분**한다. 검토 상태는 화면 및 반환값으로 제공하며 별도 보관하지 않는다. 다음 실행에서 새로 검토해야 하고, 과거 확정 상태가 유지된다고 가정하지 않는다.

## 9. 검토 결과 전달 형식과 참고 자료

검토하는 LLM은 발견한 문제의 파일·함수, 발생 조건, 실제 영향, 수정 내용, 검증 결과와 남은 한계를 구체적으로 남긴다. 실제 실행한 것과 코드만 읽어 판단한 것을 구분한다. 새 번호 생성 여부와 CSV 변경 여부도 보고한다. 근거가 없는 성능 향상 표현을 추가하지 않는다.

| 자료 | 용도 |
|---|---|
| `lotto/주간분석개선.md` | 현재 실행·검증 절차 |
| `lotto/번호선정방식.md` | 현재 번호 분산 규칙과 점수 의미 |
| `lotto/검증사용법.md` | 최종 GPT 검토 절차 |
| `lotto/실행전점검결과.md` | 최근 수정 및 검증 설명 |
| `audit_predictions.audit(...)` 반환값/출력 | 공식 대조, 기존 예측 재채점, 기법별 제외 근거 |
| `benchmark_audit.main()` 반환값/출력 | v4·현재 모델·동일 분산 균등확률·일반 무작위 비교 결과 |
| 생성 결과의 `attrs["weekly_review"]` | 해당 생성 시점의 기법·강도·집중도 |
| 저장 함수 결과의 `attrs["final_review"]` 및 최종 검토 출력 | 해당 입력의 검토 상태 |

오래된 문서나 보고서에는 이전 버전 규칙이 남아 있을 수 있다. 현재 호출 경로·버전·해시·대상 회차와 대조한 뒤 적용한다.

## 10. 검토 지적 반영 — v6, 2026-09-28

### 반영한 네 가지 문제

1. **읽기 오류 후 덮어쓰기 위험**: 예외를 빈 이력으로 처리하던 로더를 공통 엄격 로더로 교체했다. 수집 결과는 전부 검증한 뒤 저장한다. 파싱 실패, 중복 이력, 부분 수집 실패, 잘못된 공식 날짜/회차가 원본 변경으로 이어지지 않도록 했다.
2. **예측 값의 묵시적 보정**: 소수 번호 절삭, 누락 회차 추정, 잘못된 행/중복 삭제 경로를 제거했다. 필수 식별자와 번호는 검증 후 변환하고, 문제 행을 그대로 둔 채 중단한다.
3. **양수 반영 강도가 조합에 반영되지 않는 문제**: 확률 순위만 사용하던 마지막 선택 우선순위를 가중 추출로 변경했다. 노출 분산 제약은 유지하고 q 크기의 차이가 선택에 전달되도록 했다. 순위가 같은 합성 입력에서도 강도 변경이 선택에 영향을 주는지 검증한다.
4. **분산 효과와 학습 효과가 섞인 비교**: 같은 선택기·시드의 균등확률 대조군을 추가했다. 회차별 짝비교와 실제 신호 적용 회차 수를 함께 보고한다. 비교용 v4의 수치 계산은 변경하지 않았다.

### 실제 수행한 검증

- 회귀 테스트 45개 통과. 기존 35개에 CSV 손상/부분 수집/묵시적 보정 차단, 강도·가중치의 실제 영향, 균등 전환 시 동일 대조군, 짝비교 정렬 검사를 추가했다. 테스트 데이터와 출력은 임시 폴더 또는 메모리에서만 다룬다.
- 실제 CSV로 오프라인 점검도 완료했다. 로컬 이력은 1242회까지이고 시간 기준 조회 대상은 1243회이므로 `official_status=offline`, `ready_for_generation=false`였다. 저장된 과거 평가값에 불일치는 없었으며, 1243회 예측은 로컬 결과 미보유 상태로 보고했다.
- 저장된 이력 1~1242회로 1183~1242회 60개 과거 대상 회차를 재생했다. 대상 회차의 정답은 학습에서 제외하고 10세트 예산으로 비교했다. 일반 무작위는 100회 반복했다. 실행 후 결과에 맞춰 규칙이나 파라미터를 다시 조정하지 않았다.

실제 두 CSV의 바이트는 보존했으며 이번 작업에서 금주 예측 생성이나 공식 최신 결과 조회는 실행하지 않았다. 주요 처리 단계·입력/반환 의미·중단 조건·통계 해석을 코드 주석과 관련 문서에 보완했다.
