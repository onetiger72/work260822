# 로또 예측 시스템: 다른 LLM을 위한 검토 규칙

작성 기준: 2026-09-28, 생성기 버전 `screened_balanced_v5`.
프로젝트 루트는 `C:\work`, 코드·데이터 폴더는 `lotto/`이다. 아래 경로와 명령은 프로젝트 루트 기준이다.

이 문서는 현재 구현과 검토 원칙을 전달하는 참고 문서다. 다른 LLM에게 검토를 맡길 때 이 파일을 함께 제공한다. 파일명만으로 자동으로 읽힌다고 가정하지 않는다. 사용자의 최신 요청이 우선이며, 코드가 변경되면 이 문서의 버전·수치·설명도 갱신한다.

## 1. 목적과 해석 원칙

- 과거 추첨 결과 수집 → 저장 예측 재평가 → 기법 검증 및 제외 → 반영 강도 검증 → 세트 생성 → 최종 일관성 검토의 연결을 유지한다.
- 성과표를 저장하는 것과 실제 생성기에 반영하는 것은 다르다. 선택한 특징이 최종 학습 입력으로 전달되는지 호출 경로까지 확인한다.
- 로또 추첨의 예측 우위를 가정하지 않는다. 무작위 기준보다 좋다는 근거가 없으면 균등확률로 돌아간다.
- 번호를 여러 세트에 분산해 동시 실패를 줄이는 효과와, 당첨번호를 더 잘 예측하는 능력을 구분한다.
- 개별 세트 적중, 당첨, 수익, 미래 성능을 보장하지 않는다. LLM의 검토 통과도 당첨 정확성을 뜻하지 않는다.
- 사용자가 실행 전 점검만 요청하면 새 회차 번호를 생성·저장하지 않는다. 결과를 본 뒤 과거 예측을 바꾸어 성과가 좋아진 것처럼 만들지 않는다.

현재 기본 생성 흐름:

```text
주 실행 파일의 save_prediction_sets
  → 데이터 검증 및 공식 최신 결과 확인
  → 기존 예측 실제 결과 재평가
  → generate_prediction_sets 래퍼
  → lotto_portfolio.generate_prediction_sets
      → review_probabilities
          → screen_methods
          → 선택한 기법만 calibrated_probabilities에 전달
          → 결합 모델 반영 강도 결정
      → select_portfolio
  → final_review
  → 상태를 구분해 기존 형식으로 저장
```

`lotto.py`, `lotto_engine.py`, `_legacy`·`_v1` 함수, 기존 모의 선택기는 구형 또는 비교용 경로다. 이름이 비슷하다는 이유로 현재 실행 경로로 오인하지 않는다. `select_ranked_portfolio`는 집중 선택을 재현하기 위한 비교용이다. `analysis_cache/portfolio_v4.py`는 변경 전 기준 사본이므로 새 로직에 맞춰 고치지 않는다.

## 3. 공식 결과와 저장 데이터 규칙

- 공식 결과 조회는 동행복권 API `https://www.dhlottery.co.kr/lt645/selectPstLt645Info.do`를 사용하며, 요청 회차와 응답 회차를 대조한다.
- 최신 완료 회차는 한국 시간 토요일 21시를 결과 공개 확인 기준으로 계산한다. 계산된 시각만으로 결과 공개를 확정하지 않으며 공식 조회 성공이 필요하다.
- 본번호는 1~45의 서로 다른 정수 6개다. 보너스도 1~45의 정수이며 본번호와 중복되면 안 된다. 소수·불리언·비정상 값은 허용하지 않는다.
- 이력은 1회부터 마지막 회차까지 누락·중복 없이 이어져야 한다. 추첨 날짜도 회차와 일치해야 한다.
- 다음 예측 대상은 마지막 검증된 회차 + 1이다. 이미 결과를 학습한 회차나 중간 회차를 건너뛴 대상을 예측으로 취급하지 않는다.
- 일반 실행에서 최신 결과 누락, 공식 조회 실패, 공식/저장 결과 불일치는 새 예측 생성 차단 사유다. 오프라인 점검을 공식 확인 완료로 표시하지 않는다.
- 본번호 일치수는 예측 집합과 실제 본번호 집합의 교집합 크기다. 보너스 일치는 별도로 계산하며 본번호 적중수에 합산하지 않는다. `총일치수`를 본번호 적중으로 해석하지 않는다.
- 저장된 평가 숫자를 그대로 신뢰하지 말고 원래 예측번호와 공식 결과로 재계산한다.
- 기존 회차의 예측번호와 CSV 열 구조를 보존한다. 일반 실행은 평가 열을 갱신하고 없는 다음 회차를 추가할 수 있지만, 기존 예측번호를 자동 교체하지 않는다.
- 과거 예측에는 추첨 전 생성 시점을 입증할 자료가 부족하다. 저장 기록 비교와 사후 재생성 백테스트를 실전 예측력 인증으로 표현하지 않는다.

## 4. 시간 순서와 기법 선별 규칙

### 학습과 특징

- 대상 회차의 특징을 계산할 때는 반드시 그 추첨 직전까지의 이력만 사용한다. 평가 대상 또는 이후 회차의 결과가 학습·특징·가중치 선택에 들어가면 데이터 누수다.
- 본번호 포함의 균등 기준은 번호당 `6/45`이다. 현재 보정기는 최근 최대 120개의 과거 학습 사례와 ridge 계수 `120.0`을 사용한다.
- 선형 편차는 0.5배로 줄이며, 포함 추정치는 `[0.04, 0.30]` 범위 및 합계 6 조건으로 보정한다. 이 수치는 모델 설정이지 실제 번호별 당첨 확률을 입증한 값이 아니다.
- `보너스보조신호`는 본번호 보정 특징에서 제외한다. 다른 기법이 과거 보너스를 참고할 수 있다는 것과, 평가 정답에 보너스를 넣는 것은 별개다.

### 기법 선택 구간

- 최근 24회보다 앞선 24회에서 각 기법의 단독 보정 모델을 순차 평가한다.
- 유지 조건은 평가 회차 최소 12개이며, 균등확률 대비 평균 Brier 오차 개선이 회차별 개선 차이의 표준오차 2배를 넘어야 한다.
- 기준 미달 기법은 최종 보정 학습 입력에서 실제로 제외한다. 다음 실행에서 다시 평가하므로 영구적인 코드 삭제와는 다르다.
- 이 규칙은 보수적인 선택 기준이다. 다중 비교까지 보정한 통계적 유의성 검정이나 미래 성능 입증으로 설명하지 않는다.

### 후속 반영 강도 구간

- 선택한 기법을 고정하고, 그 뒤 최근 24회에서 결합 모델과 균등확률의 혼합 강도 `0%, 25%, 50%, 100%`를 비교한다.
- Brier 오차가 가장 낮은 후보와의 회차별 차이를 사용한다. 최저 오차와 표준오차 이내인 후보 중 가장 약한 강도를 선택한다.
- 검증 자료가 부족하거나, 선택한 기법이 없거나, 강도가 0%이면 균등확률을 적용한다.
- 최종 적용 기법은 보고서의 `effective_methods`로 확인한다. `selected_methods`가 있어도 강도가 0%이면 실제 적용 기법은 없다.
- 기법 선별과 강도 검증에 사용한 성적은 튜닝 자료다. 별도의 바깥 구간 검증 또는 미래 실전 검증 없이 독립 성능으로 주장하지 않는다.

### 새 기법 추가

- `ANALYSIS_METHODS`에 등록하고 번호 1~45에 대한 유한한 점수를 반환하도록 구현한다. 특징 계산은 전달받은 과거 이력만 사용해야 한다.
- 새 기법도 동일한 선별·강도 검증 경로를 거쳐야 한다. 최근 실패 한 회차의 당첨번호를 우대하거나 검증 없이 높은 가중치를 부여하지 않는다.
- 기존 실전 피드백 CSV와 LLM 가중치 제안은 현재 생성기의 직접 입력이 아니다. 저장·출력되고 있다는 이유로 반영됐다고 말하지 않는다.
- 결과를 본 뒤 기준을 반복 조정하면 그 평가 구간은 더 이상 독립 검증이 아니다. 변경 근거와 새로운 검증 구간을 명시한다.

## 5. 10세트 선택 규칙

- 기본은 서로 다른 본번호 6개로 이루어진 10세트다. 현재 선택기 인수는 1~10세트를 지원하나, 전체 45개 포함 설명은 10세트 기준이다.
- 선택 우선순위는 번호별 기존 사용 횟수 최소화 → 같은 번호쌍 재사용 최소화 → 높은 모델 추정치 → 고정 시드 동률 처리다.
- 10세트는 1~45 전체를 포함하며 번호당 최대 2회 사용한다. 동일 입력과 동일 시드는 동일 결과를 내야 한다.
- 45개를 모두 포함하므로 10세트 전체가 본번호 0개가 되는 경우를 구조적으로 막는다. 이것은 개별 세트 적중이나 당첨을 보장하지 않으며 예측력 개선 증거도 아니다.
- 한 세트 안 중복, 범위 오류, 동일 세트 중복, 일부 번호의 과도한 집중을 확인한다. 번호쌍 중복 감소는 선택 우선순위이며 별도의 최적화 보장으로 과장하지 않는다.
- `조합점수` 및 저장 CSV의 `종합점수`는 해당 번호들의 포함 추정치 합이다. 1등 당첨확률이 아니다. 균등확률이면 세트당 점수는 0.8이다.
- 과거 상위 점수 조합만 고르던 방식으로 되돌리려면 번호 집중과 회차별 최고 적중 저하를 포함해 검증해야 한다.

## 6. 점검 모드와 최종 검토 상태

```powershell
# 새 번호 없이 공식 결과 조회 및 로직 점검
python "lotto/로또 당첨번호 예측.py" --audit-only

# 네트워크 없이 로컬 점검: 공식 확인 완료가 아님
python "lotto/로또 당첨번호 예측.py" --audit-only --offline

# 실제 수집·평가·다음 회차 생성 작업을 요청받았을 때 사용
python "lotto/로또 당첨번호 예측.py"

# 저장된 다음 회차 후보 검토: 새 번호 생성용 명령이 아님
python lotto/review_predictions.py
```

- `--audit-only`는 `실행전점검.json`을 저장한다. 공식 새 결과는 메모리 및 보고서에 반영하며 당첨 이력·예측 CSV를 변경하지 않는다. 같은 이름의 이전 점검 보고서는 갱신된다.
- 일반 실행의 최종 검토는 전체 후보, 직전 예측 비교, 공식 대조 상태, 입력 SHA256, 대상 회차 및 검토한 세트 ID를 확인한다.
- `LOTTO_FINAL_REVIEW_MODE`는 기본 `manual`, API 모드는 `api`다. 기존 가중치 감사용 `LOTTO_LLM_MODE`와 혼동하지 않는다.
- API 키는 환경변수로만 제공하며 코드·CSV·보고서·대화에 기록하지 않는다.
- 입력이 달라지면 이전 검토 제안을 재사용하지 않는다. 수동 제안 파일은 로컬 검토 기록이며 모델 신원을 인증하는 서명이 아니다.
- 공식 일치와 유효한 `pass`가 함께 있어야 `finalized: true`가 된다. 이는 데이터·후보의 일관성 검토 통과를 뜻한다.
- 현재 저장 흐름은 `validation_error`, `source_mismatch`, `reject`에서 중단한다. 검토 대기 후보는 CSV에 저장될 수 있으므로, **파일에 존재한다는 것과 최종 확정을 구분**한다. 저장 CSV 자체에 확정 상태가 없으므로 `GPT최종검증결과.json`을 함께 확인한다.

## 7. 검증·캐시·변경 규칙

```powershell
python -B -m unittest discover -s lotto -p "test_lotto*.py" -q
python -B lotto/benchmark_audit.py
```

- 변경 전 현재 코드와 작업 트리 상태를 읽는다. 사용자의 수정 또는 이전 검토 산출물을 무단으로 되돌리지 않는다.
- 데이터 유효성, 본번호/보너스 분리, 추첨 이전 학습, 기법 유지/제외, 검증 구간 분리, 번호 분산, 공식 조회 실패, 점검 모드 CSV 보존을 회귀 검증한다.
- 기존 방식과 수정 방식은 같은 대상 회차·동일한 10세트 예산으로 비교한다. 무작위 기준도 같은 예산으로 여러 번 반복한다.
- 세트당 평균 적중, 회차별 최고 적중, 전체 0개 회차, 3개 이상 적중 등을 함께 보고한다. 유리한 지표 하나로 성공을 선언하지 않는다.
- 특징 캐시는 동일한 불변 과거 이력과 동일 특징 코드에만 재사용한다. 길이가 같다는 이유만으로 다른 데이터의 캐시를 쓰지 않는다. 검증용 `benchmark_audit.py`는 실행 중 새 캐시를 만든다.
- 데이터 해시, 생성기 버전, 검증 범위, 선택 규칙, 시드 조건을 남긴다. 코드 변경 시 문서와 보고서 설명도 일치시킨다.
- 비교용 원본·기존 예측은 보존한다. 회고 생성 결과를 실제 추첨 전 예측 이력에 덮어쓰지 않는다.

## 9. 검토 결과 전달 형식과 참고 자료

검토하는 LLM은 발견한 문제의 파일·함수, 발생 조건, 실제 영향, 수정 내용, 검증 결과와 남은 한계를 구체적으로 남긴다. 실제 실행한 것과 코드만 읽어 판단한 것을 구분한다. 새 번호 생성 여부와 CSV 변경 여부도 보고한다. 근거가 없는 성능 향상 표현을 추가하지 않는다.

| 자료 | 용도 |
|---|---|
| `lotto/주간분석개선.md` | 현재 실행·검증 절차 |
| `lotto/번호선정방식.md` | 현재 번호 분산 규칙과 점수 의미 |
| `lotto/검증사용법.md` | 최종 GPT 검토 절차 |
| `lotto/실행전점검결과.md` | 최근 수정 및 검증 설명 |
| `lotto/실행전점검.json` | 공식 대조, 기존 예측 재채점, 기법별 제외 근거 |
| `lotto/실행전비교.json` | v4·v5·무작위 비교 결과 |
| `lotto/주간분석검토_회차.json` | 해당 생성 시점의 기법·강도·집중도 기록 |
| `lotto/GPT최종검증결과.json` | 해당 입력의 최종 검토 상태 |

오래된 문서나 보고서에는 이전 버전 규칙이 남아 있을 수 있다. 현재 호출 경로·버전·해시·대상 회차와 대조한 뒤 적용한다.
